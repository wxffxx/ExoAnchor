# 两步验证：TOTP 动态验证码

Dev 和 Stable 的管理员账户可启用两步验证。启用后，浏览器、Toolkit 和 MCP 的新登录均须提交密码以及验证码（或一次性恢复码）。设备随后签发普通会话 token；已有会话的正常 API 操作无需每次输入验证码。

## 启用与使用

1. 在 HTTPS 页面登录，打开 Settings 的账户与安全区域，找到“两步验证”。先确认设备时间已就绪；开始设置前须在最近 60 秒内重新登录。
2. 输入当前密码，点击“设置两步验证”。将显示的密钥手动添加到验证器，选择基于时间，也可点击本机验证器链接。格式为 SHA-1、6 位数字、30 秒周期，与 RFC 6238 兼容。
3. 保存全部 8 个恢复码。恢复码只在此次设置期间显示，各含 128 bit 随机值，设备仅保存其 SHA-256 摘要。
4. 勾选已保存，重新输入当前密码和验证器验证码，在 5 分钟内“确认启用”。确认前不会启用两步验证。取消或超时后重新开始即可。
5. 启用后所有旧浏览器/MCP 会话及尚未领取的登录结果均失效。确认启用所用的验证码已被消耗，等待下一组验证码后重新登录。

每个验证码时间窗口只接受一次，并接受相邻的前后一个 30 秒窗口。成功校验会持久化已使用窗口；重启不会恢复其使用资格。设备时间回退时，已接受窗口及更早窗口会继续被拒绝。修改账户信息需重新登录，账户表单也提供验证码输入框。

## 恢复与停用

- 登录时可在验证码栏输入一个尚未使用的 32 位十六进制恢复码；仍需账户密码。恢复码不依赖网络校时，使用后立即持久化作废。
- 停用需要最近 60 秒内的浏览器登录、当前密码，以及一个新的验证码或另一枚未使用的恢复码。成功后再次撤销所有会话。
- 如需更新密钥或恢复码，先停用，再重新设置。停用前应确认仍持有有效验证码或恢复码。
- 设备重启后通过 `pool.ntp.org` 的 SNTP 获取时间。时钟未就绪时不可开始设置或使用 TOTP，登录提示会说明等待校时或使用恢复码。没有额外增加客户端时间覆盖入口。
- 所有验证器与恢复码均丢失时，没有远程密码绕过。必须使用拥有物理访问权限的本地清除配置/重新初始化流程；清除整份 NVS 会同时删除其他设备设置。单独重设账户密码不会清除两步验证记录。

## 软件客户端

Toolkit GUI 的网络连接区域提供“动态验证码 / 恢复码”。CLI 可使用 `--otp-code`，也可通过 `EXOANCHOR_OTP_CODE` 提供一次性输入。MCP 支持 `EXOANCHOR_OTP_CODE` 或 `EXOANCHOR_OTP_CODE_FILE`，与现有密码和设备证书配置一起使用。

客户端仅在下一次密码登录时发送 `otp`，随后清空内存中的待发送值；失败请求也会消耗该输入，自动重试不会复用它。MCP 环境/文件在启动配置时读取，后续会话到期须提供新验证码并重新启动该客户端。不要把验证器密钥交给客户端自动生成验证码。启用两步验证后，旧客户端需要更新或使用经双因子认证获得的现有会话 token。

## API 与保护规则

- `POST /api/auth/login` 增加可选字符串 `otp`（最多 32 字符）；未启用两步验证的设备保留原登录行为。用户名、密码、动态码共同校验通过后，异步登录结果才允许创建会话。
- `GET /api/auth/status` 增加 `two_step_enabled`、`two_step_time_ready`、`two_step_storage_ok`，不包含密钥和恢复码。
- `GET /api/auth/two-step` 仅接受浏览器设置会话，返回启用、存储、时间状态和恢复码剩余数。
- `POST /api/auth/two-step` 接收 `action`（`begin`、`confirm`、`disable`）和 `current_password`。`confirm` 还需要 `enrollment_id` 与 `otp`；`disable` 需要 `otp`。只有 `begin` 的成功响应返回密钥、`otpauth_uri` 与恢复码。
- 连续 5 次动态码失败后锁定 30 秒；正确密码不能清除该计数。存储读取错误、损坏记录或失败的写入会拒绝认证，不能退化为密码登录。启用/停用会更新凭据代数并撤销会话，避免在途登录领取旧权限。

密钥保存于设备 NVS，保密能力取决于设备现有存储与物理访问保护；本功能没有新增 NVS 加密或安全启动。普通 SNTP 也不提供认证时间源。Web 与客户端应继续使用已配对的 HTTPS；两步验证不替代传输保护。

## 验证范围

`test_two_step_runtime.py` 执行两套固件的生产 C 代码，验证 RFC 4226/6238 向量、窗口与重放、重启、限流、恢复码、存储失败及启停状态。`test_two_step_http_runtime.py` 执行实际异步登录处理函数，验证浏览器/MCP 均不能仅凭密码签发会话。现有账号测试覆盖代数更新与会话撤销，浏览器和 Python 客户端测试覆盖动态码传递与清理。

所有测试均为主机模拟；本地 UI mock 的状态也仅用于页面预览。真实设备 SNTP、断电写入行为、验证器互操作和硬件验收仍需在授权的真机测试中验证。

标准：[RFC 6238](https://www.rfc-editor.org/rfc/rfc6238)、[RFC 4226](https://www.rfc-editor.org/rfc/rfc4226)；配对见 [HTTPS 指南](SECURITY_TRANSPORT_zh.md)。

# 模型策略

ExoAnchor 的模型策略服务于裸机恢复闭环，而不是追求单一模型或单一部署形态。

## 当前原则

1. MVP 不要求本地小模型独立完成系统管理任务。
2. 云端强模型应作为一等 provider 保留，包括 DeepSeek、Gemini、OpenAI 等。
3. 本地模型适合做低风险、低延迟、可降级的辅助任务，而不是首版核心决策依赖。
4. 工程重点先放在结构化 observation、可审计日志、安全闸门和可恢复 runtime。
5. 模型输出不能直接绕过后端 policy 执行危险动作。

## 任务分层

| 层级 | 建议模型策略 |
|---|---|
| 简单分类、状态摘要 | 可用本地或轻量模型 |
| 屏幕理解、故障解释 | 优先使用稳定 vision / multimodal provider |
| 计划生成、恢复建议 | 使用强模型，结果进入后端计划和安全检查 |
| 高风险动作 | 模型只能建议，执行必须经过后端 policy 和人工确认 |

## 对 Agent 的要求

- Provider 应可配置，而不是写死在 UI 或 prompt 中。
- 每次模型调用应记录任务、输入摘要、输出摘要、provider、模型名和时间。
- 模型建议必须转换成结构化计划或工具调用，再进入 executor。
- 失败时应保留原始 observation，方便换模型或人工复盘。

## 非目标

- 不把本地小模型作为首版硬依赖。
- 不把“模型能猜对”作为系统可靠性的来源。
- 不让前端直接执行模型输出的危险命令。

## 编号规则

- 固件版本和 PCB 版本是两套独立编号。
- `V2.3b4`、`V2.3b6`、`V2.4a6` 是硬件标识，不是固件补丁号。
- `v0.86.6-dev/` 是源码目录名；当前目录内运行版本已经演进到
  `0.87.6-dev`。
- Dev 检查点不等于 RC 或正式发布。
- 未找到完整源码或产物的历史编号不作为已验证版本。

#### 0.87.6 自动化与人工控制边界（2026-08-22）

- 以统一资源状态管理电源、HID、UART、SSH、视频配置、视频硬件和系统维护，Agent、MCP 与 SYSTEM 操作均携带 actor、operation ID、run ID 和精确 generation。
- 顶部导航统一显示自动化正在使用的资源；冲突的人工输入临时禁用，读共享的视频观察保持可用，操作者可用当前 generation 精确终止，不会误停后来启动的任务。
- UART 与 SSH 自动化输入通过 Terminal 状态和回放同步给当前页面；人工 Terminal 与自动化写入互斥，结束、取消、会话撤销和异常退出都必须释放所有权。
- KVM 与 Agent/MCP 共享只读 JPEG 帧；只有 HID 输入接管才阻断人工输入。视频观察按认证 principal 区分 Agent 与 MCP，并在开始、actor 切换和释放时更新 epoch，防止停止后被旧长流 keepalive 复活。
- Prototype V2.4 的最终 `0.87.6-dev` 镜像已在身份登记表中精确核验的 rev3.2、16MB Flash 实机上通过应用区写入、独立 digest、启动状态和 MCP 视频 actor/generation/精确人工终止回归；逐板 CH343 serial 与 eFuse MAC 仅保存在不入库的受控身份记录中。应用 SHA-256 为 `e7bf95b20f231ed8b8abc0b298ba99c72f1798c0f0a41881469c9d95fb4e1c06`。该检查点不自动提升为 RC/Stable，也不关闭 Runtime V2 生产切流硬门。

#### 0.87.5 Settings 信息架构整理（2026-08-20）

- Settings 导航的非被控端项目统一使用设备主题色状态点；被控端两项继续使用蓝色点，文字与状态语义色不变。
- 设备页按“设备基础、网络设置、KVM 与 HID、设备诊断摘要、只读 GPIO 矩阵”排序；只读 GPIO 矩阵固定在末尾。
- “视频采集常在线”“返回 KVM 自动刷新”和“MS 视频电源”归并到一个视频运行卡片。
- MS2109 的 GPIO 电平、时序、操作次数、结果、重新上电和手动刷新属于调试面，不再暴露在产品 Settings。

#### 0.87.4 已纳入主线的 Locator LED 反转（2026-08-19）

- 保留 Overview 的 Locator LED 亮/灭控制，Settings 仅提供双 GPIO 硬件的灯色/方向反转，避免重复的实时开关。
- 板型通过 `CONFIG_SI_POWER_LOCATOR_RETURN_GPIO` 声明第二输出；未声明时 API 返回不支持，前端不开放反转控件。
- 关闭时两路均拉低；开启时只有一路为高，反转会交换高电平所在 GPIO，并立即应用到当前点灯状态。
- 反转选择使用 `si_power/loc_rev` 持久化，设置失败时回滚输出方向；GPIO 映射重置同时恢复正向。

#### 0.87.4 KVM 恢复与操作能力范围

焦点恢复：

- 在 KVM 页面提供“返回页面时自动刷新视频”开关，默认开启，并记住用户选择；
- 只有窗口或页面确实经历过失焦、隐藏后重新获得焦点或变为可见时，才主动刷新一次视频；
- `focus` 与 `visibilitychange` 同时触发时必须合并为一次刷新，避免重复重连和刷新风暴；
- 开关关闭后，焦点变化不得影响当前视频流，用户仍可手动刷新；
- 自动刷新沿用现有视频恢复路径和无画面占位 Logo，不创建第二套采集生命周期；
- 使用真实浏览器验证开关持久化、标签页切换、窗口切换、短时间反复聚焦、黑屏恢复和正常视频不中断；

实时视频统计：

- 在 KVM 页面重新显示当前实际帧率和当前视频码率，并随视频流持续更新；
- 帧率表示实际交付到 KVM 视频流的帧数，码率表示该视频流在滚动时间窗口内的实际数据量，不使用目标 FPS、视频模式标称值或 CSI lane bitrate 冒充；
- 统计更新不得为每个浏览器额外启动一条采集链路，也不得通过高频独立 HTTP 轮询增加主线程阻塞；
- 视频未连接、正在恢复或样本不足时显示明确的占位状态，不保留过期数字；

BIOS / Boot Menu 循环按键：

- 在 KVM 页面重新提供“循环 Del 进入 BIOS”和“循环 F11 进入 Boot Menu”入口；
- 复用现有 `/api/host/boot-key`、有界按键序列和 HID 租约，不在浏览器里用无界定时器直接重复发键；
- 启动后显示当前按键、已发送次数、剩余时间和停止按钮；达到次数或时间上限后必须自动停止并释放全部按键；
- 由当前 KVM 页面显式启动的序列允许用户继续观察视频，但任何人工键盘或鼠标操作、页面退出、控制租约被抢占或点击停止都应立即取消序列；
- 不自动判断已经进入 BIOS，也不自动操作未知 BIOS 菜单；完成后仍由用户根据实时 KVM 画面确认结果；
- 使用真机分别验证 Del、F11、人工停止、超时停止、HID 未就绪、页面切换和重复点击不会产生遗留按键或后台无限任务；

Settings 产品化二元开关：

- 对 Settings 中所有 T/F 控件做一次产品语义审计；开关只用于可持续、可逆且用户能理解后果的二元能力，不把一次性操作、实时状态或多选模式伪装成开关；
- “安全与访问”保留或补齐：允许外部 MCP、自动退出、允许局域网发现；自动退出关闭后仍保留服务端 24 小时会话上限；
- “KVM 行为”保留或补齐：保持视频常在线、返回 KVM 时自动刷新；后者同时作为 KVM 页面的快捷开关，并明确标注作用于当前浏览器；
- “Agent 与隐私”仅在编译了内置 Agent 的 Dev 产品中显示：启用内置 Agent、允许联网搜索、允许附带当前页面上下文、保存对话历史、允许长期记忆、显示 Agent 操作过程；
- 本地 Agent 与外部 MCP 的逐项工具能力继续使用彼此独立的开关；工具风险等级和 observe/supervised/autonomous 属于策略选择，不伪装成 T/F；
- “更新与隐私”预留自动检查更新和发送匿名诊断两个开关；自动安装固件在签名 OTA 与可靠回滚完成前不开放，匿名诊断只有在服务端真实存在时才显示且默认关闭；
- 每个开关必须显示明确名称、关闭后的影响、默认值和保存范围（设备全局、当前账户或当前浏览器），不得只写抽象的 enabled/disabled；
- 依赖当前构建或板型能力的开关应直接隐藏，不显示永远不可用的灰色占位项；
- Locator LED 亮/灭、键盘直通和 Direct Click 是实时控制或当前 KVM 会话模式，不作为持久产品设置；双 GPIO Locator 的灯色/方向是板级配置，可在高级设置中持久保存；
- 清空密码、Reset Everything、重启、进入 BIOS、循环 Del/F11、导出诊断包和恢复默认值是一次性操作，必须使用按钮与确认流程，不做成开关；
- DHCP/静态地址、UART 波特率、模型 Provider、权限模式和日志级别具有两个以上选项，必须使用单选、分段选择或下拉框，不做成开关；
- 实时 FPS 与码率默认显示，不设隐藏开关；只有 frame age、丢帧、capture owner 等扩展诊断信息可以放进默认关闭的诊断详情；
- 不开放关闭认证、绕过审批、无限 HID 循环、任意 Flash/NVS 写入或任意 GPIO 电平写入等破坏产品安全边界的开关；

#### 量产单 CH343 与 UART0 边界（2026-08-01）

量产版本只搭载一颗 CH343 时，不再沿用 PrototypeV2.3 的双 CH343 假设。
量产实现采用以下职责边界，具体 GPIO 和连接器仍需以量产网表冻结：

- 唯一的板载 CH343 专用于被控主机终端，连接 ESP32-P4 的目标 UART；
- ESP32-P4 原生 USB Serial/JTAG 作为设备维护平面，承担本机诊断 CLI、
  工厂烧录和恢复；正常升级优先使用网络 OTA；
- UART0 是完整通用 UART：正常启动后可运行日志、诊断 CLI 或受控协议，
  进入 Joint Download Boot 后由 ROM 下载器接管；两种用途只能分时独占；
- CLI、原始协议和 UART OTA 可以由固件中的单一 UART 所有者在运行时切换，
  但标准 `esptool` 烧录必须复位进入 ROM，不能与运行时终端并行；
- 一颗 CH343 不能同时服务两个 USB Host。若用硬件 MUX 在 UART0 与目标 UART
  间切换，选择信号必须在 P4 复位期间保持，且维护模式之外必须隔离
  DTR/RTS 与 GPIO35/EN；该方案只作为备选，不作为默认量产架构；
- Toolkit 必须把烧录定义为独占状态：关闭维护终端、锁定原设备身份、烧录、
  等待同一 USB 设备重新枚举、确认版本和板型，再恢复可用状态；
- 工厂/恢复接口必须保留 USB D+/D-、GPIO35、GPIO36、EN 和 GND 测试点。

当前 PrototypeV2.3 仍保留 UART0 主控制台与 USB Serial/JTAG 次级输出；次级
控制台不接受 CLI 输入。量产 profile 需要在量产网表确认后改为原生 USB
Serial/JTAG 主控制台，不能在未知硬件上提前复用 PrototypeV2.3 profile。

仍未形成正式发布能力的项目包括：

- 完整持久 Thread/Turn/Plan/Step；
- 跨重启安全恢复和通用幂等动作；
- 持久请求队列与完整 Verification；
- 签名 OTA、自动回滚和正式 NVS schema migration；
- 完整 HIL、故障注入和长期稳定性回归；
- V2.3 b4/b6 最终身份复核；
- MS2109 1080p 有效细节问题闭环。
